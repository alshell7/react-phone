## Live PBX

Verified against the supplied production PBX (`AzeerPBX`, Asterisk realm) with the updated WSS account for extension 7001. Credentials live only in the git-ignored `.env.local`.

| Check                                    | Result                                                                                                                                                                                                                                                         |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run test:live` (real JsSIP in Node) | Pass, 3/3: digest registration over WSS in ~0.5 s, foreground refresh, re-registration on reconnect with the same client, clean unregister, no password in any event, and the unreachable-server timeout path                                                     |
| `npm run test:live:call` (web build, Chromium, fake microphone) | Pass: registration through the playground's Connection form (password cleared afterwards), keypad dialing of `*97` (voicemail), digest-challenged INVITE answered with `200 OK`, real remote audio driving the stats-based bars to `speaking`, mute/unmute, hold **and resume**, DTMF, hangup, and the Recents entry. Confirmed step by step from the Playwright trace |
| Destinations probed                      | `*97` answers; `*43` returns `183 Session Progress` without answering within 30 s, so the probe cancels it                                                                                                                                                       |
| Bug found and fixed                      | A quick Resume after Hold failed with "Hold is temporarily unavailable" because JsSIP reports hold before the PBX answers the re-INVITE; hold/resume now retries until negotiation settles (unit-tested)                                                       |

History: the first supplied credentials (extension 7002) were rejected with `401` after a correct MD5 digest exchange; the web package's own playground was rejected identically from the same machine, confirming the credentials rather than the code. The plain-SIP line (`T6_7001_1`) does not accept WebSocket registration, so two-party calls between the supplied lines are not possible from a browser; the local registrar test covers two-party calls instead.

## Not verified here

- Native iOS and Android builds on devices or emulators (this machine has no Xcode, and the Android SDK install was skipped by choice). The example app is configured for both (`expo prebuild` with the WebRTC config plugin, microphone permission text, Android permissions, iOS background modes).
- Speaker routing with a real audio session, Bluetooth routes, proximity sensor, and system ringtone.
- REFER transfer and SIP INFO DTMF (the device path) against the production PBX, and TURN on mobile networks. Hold/resume and RFC 2833 DTMF were verified live from the web build.
- CallKit/ConnectionService and push-woken incoming calls (outside this release).

Preview-mode calls in tests and screenshots are explicitly simulated. No live account, server, or password is bundled in the source, playground, documentation, or generated embed code.
